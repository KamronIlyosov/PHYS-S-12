Week 09 · Networking

Radio, WiFi, Bluetooth (IoT)

Siri controlled LEDs running on a XIAO ESP32-C3.

What this is

The point of the assignment was to get a microcontroller talking over a network, and the most satisfying version of that for me was being able to turn LEDs on and off with my voice through Siri. The chain works like this, my phone takes the voice command "Turn the lights on" and runs a Shortcut, the Shortcut sends an HTTP GET request to the IP of my XIAO ESP32-C3 on the local network, the ESP32 receives the request and flips a digital pin which drives the LEDs. So a sentence at one end ends up as electrons moving through an LED on the other.

Step 1: Materials

  • XIAO ESP32-C3 microcontroller
  • USB-C cable for programming and power
  • Breadboard
  • 22 LEDs of any color (they all wire in parallel)
  • 1 × 330Ω resistor
  • 3 pin to pin jumper wires
  • iPhone with the Shortcuts app installed (any modern iPhone has this preinstalled)

Step 2: Wiring the circuit

The wiring is as simple as it gets. All 22 LEDs are on the breadboard in parallel, with their long legs (anodes) connected together and tied to digital pin D2 on the ESP32, and their short legs (cathodes) all tied to the GND pin on the ESP32. The 330Ω resistor goes in series with the LEDs to keep the current safe.

  • LED anodes (together) → D2 on the ESP32
  • LED cathodes (together) → GND on the ESP32

Step 3: Programming the ESP32-C3

The Arduino sketch does 3 things, it connects to the local WiFi, it starts a small HTTP server on port 80, and it registers 2 endpoints, /on turns the LED pin HIGH and /off turns it LOW. Once it's running, any device on the same WiFi network can send the ESP32 a URL and the LEDs will respond. The Serial Monitor prints the IP address the ESP32 was assigned, which I needed to know so I could plug it into the iOS Shortcut later.

The code

#include <WiFi.h>
#include <WebServer.h>

const char* ssid = "MAKERSPACE";
const char* password = "12345678";

WebServer server(80);

void handleOn() {
  digitalWrite(2, HIGH);
  server.send(200, "text/plain", "LED is ON");
}

void handleOff() {
  digitalWrite(2, LOW);
  server.send(200, "text/plain", "LED is OFF");
}

void setup() {
  Serial.begin(115200);
  pinMode(2, OUTPUT);
  digitalWrite(2, LOW);

  WiFi.begin(ssid, password);
  Serial.print("Connecting to WiFi");
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }
  Serial.println();
  Serial.print("Connected! IP address: ");
  Serial.println(WiFi.localIP());

  server.on("/on", handleOn);
  server.on("/off", handleOff);

  server.begin();
  Serial.println("HTTP server started");
}

void loop() {
  server.handleClient();
}

Step 4: Siri Shortcut

Once the ESP32 is running its little server, anything that can fire an HTTP request can control the LEDs. I could open Safari and type the URL directly and it would work, but the assignment was about voice, so I made 2 Siri Shortcuts in the iOS Shortcuts app. Each one uses the built in "Get Contents of URL" action, which is just a way of sending an HTTP request without writing code. I gave them voice phrases like "Turn the lights on" and "Turn the lights off" so I could trigger them from Siri or the lock screen.

  • Turn LED On → GET http://192.168.0.194/on
  • Turn LED Off → GET http://192.168.0.194/off

Step 5: Testing

To make sure everything was working I went through it in order:

  1. Plugged in the ESP32 and opened the Serial Monitor to read the IP address it got from the WiFi router.
  1. Opened a browser and typed in the URL with /on and /off to confirm the endpoints respond. The LEDs flipped immediately and the page showed "LED is ON" / "LED is OFF" so the server side was working.
  1. Triggered the Shortcuts with voice ("Hey Siri, turn the lights on" / "Hey Siri, turn the lights off"). The LEDs flipped basically instantly, with maybe a quarter second of latency total from end of sentence to LED state change.

Step 6: What I'd do next

This setup only works on the local network because the ESP32 is on a private IP, so it's not reachable from outside the house. If I wanted to control the LEDs from anywhere I'd either integrate with Homebridge (which exposes the ESP32 to Apple's HomeKit through a Raspberry Pi or similar) or set up port forwarding through a public service, but for a class project the local network version is more than enough.

It would also be straightforward to use this same pattern for non LED stuff, just swap the output to a relay, a motor driver, or anything else. The web server side of the code doesn't care what's on the other end of the digital pin.

What I took away

The big idea this week is that "networking" on a microcontroller isn't all that different from running a tiny web server on a laptop, the ESP32 just has way less RAM. Once I had the pattern down (connect to WiFi, define endpoints, handle clients in the loop), I could see how a hundred different IoT projects would all use basically the same code with different handlers. Siri integration through Shortcuts is mostly a UX trick on top, but it's a fun one.
